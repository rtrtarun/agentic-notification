# traces

Groups stored events that share a `traceId` into runs: ordered steps (depth from the parent chain), totals (duration, tokens, cost, retries, failures), worst attention class and a status read from the last step. Events are read oldest first and steps sorted with a stable sort, so steps stored at the same instant keep the repository's order (`created_at`, then `id`); traces that ended together are ordered by trace ID. The Java service copies this exactly (milestone 39a). Pure functions over `event.Event`; it decides nothing and calls no model. Telemetry is read from `payload.metadata`. See [docs/milestones/milestone-31.md](../../../../docs/archived/milestones/milestone-31.md).
