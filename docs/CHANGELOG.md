# Changelog

Every change to this repository is recorded here, newest first. Milestone-level detail lives in `docs/milestone-N.md`; this file is the running index. Update it in the same commit as the change.

## Unreleased

### Changed
- Renamed `pkg/learning` to `pkg/ollama` (the package is the Ollama client, not the Milestone 9 learning engine) and removed the unused `learningService` field and import from `pkg/server/server.go`. No behaviour change; build and tests pass.

### Added
- Milestone 30, part 1 of 2 (Strict rules, payload predicates, per-rule channels, see [milestone-30.md](milestone-30.md)): `ParseRules` now rejects misspelt keys (`KnownFields`); rules can match on event contents with `when.payloadMatch` (`eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `exists` on dotted payload paths plus normalised `branch`, `author`, `severity`; a missing field never matches); `then.channels` routes a rule's events to dedicated channels and is refused on critical rules (and ignored by the engine if set directly). Predicates and channels are validated when saved; the worker routes by them too; dry runs accept a sample `payload`. **Part 2, per-person preferences, overrides and digests, is not done** and needs a design ruling (see the milestone doc). Go module passes locally.
- Milestone 29 (Async worker and attention budgets, see [milestone-29.md](milestone-29.md)): new `pkg/budget` (rolling-window interruption cap; `MemoryBudget`, and `RedisBudget` over one atomic Lua script) and `attention.Worker`, which drains events saved as queued and pending from the events table with `FOR UPDATE SKIP LOCKED` and leases, and releases events held for quiet hours when they end. Standard events past `ATTENTION_BUDGET_PER_HOUR` (default 10, 0 off) become `budget_exceeded`, are explained, and are included in the next digest, never dropped; background events, "always notify" choices and critical events are exempt. `ATTENTION_ASYNC` (default off) defers the attention step to the worker. Critical events are never deferred, budgeted, claimed, or changed by the worker; five independent tests prove it. New columns on `events`, `ATTENTION_WORKER_INTERVAL`, shared Redis client, CI now runs on `feature/**` branches with Redis. Go module passes locally; PostgreSQL queue and Redis script not run locally, CI runs them. The default budget changes behaviour for busy workspaces.
- Milestone 28 (Learning engine, see [milestone-28.md](milestone-28.md)): new `pkg/learning` turns stored feedback (dismissed, never, opened, reply, always) into reviewable suggestions: let Attention refine a rule, demote or promote a rule, or add a scoped override. Critical events and locked or critical rules are never suggested for and cannot be changed by a suggestion (checked when suggesting and again when applying); feedback from before an applied suggestion is ignored. New `GET /api/learning/suggestions`, admin-only `POST .../{id}/apply` (audited) and `.../{id}/dismiss`, table `learning_suggestions`, `LEARNING_MIN_SIGNALS`, `LEARNING_LOOKBACK`, and a "Suggestions from feedback" panel on the Rules screen that works in demo mode. 220 Vitest tests; Go module passes. PostgreSQL repository not run locally; CI runs it.
- Milestone 27 (Verification, see [milestone-27.md](milestone-27.md)): store contract tests written once and run against the in-memory stores always and against PostgreSQL under `-tags integration` for `pkg/delivery` (retry backoff, dead letter, manual retry, lease recovery, competing workers), `pkg/auth`, `pkg/feedback`, `pkg/overrides` and the digest store; new `pkg/db/dbtest`; a migration test that guards all eight tables and their lookup indexes; replay tests through the real Ollama and Claude clients covering redaction on the wire, critical events making no request, breaker trip and recovery, rate cap and hostile answers. No product code changed. The integration tests were not run on the development machine (no Docker or PostgreSQL available); CI runs them.
- [upcoming-milestones.md](upcoming-milestones.md): proposed milestones 27 to 31 (real-service verification, learning engine, asynchronous attention, per-person digests, production hardening), drawn from the known limits of milestones 22 to 26. Proposals only; no code.
- Milestone 26 (Language-model adapters, see [milestone-26.md](milestone-26.md)): Attention Intelligence can now use a local Ollama model or the Claude API. New `pkg/attention/llm` (one `Model` implementing Classifier, Summarizer and Explainer over a small `Completer` interface), `pkg/claude` (Messages API client, no SDK) and `ollama.Completer`. The heuristic stays the default and the fallback: a timeout, outage, open circuit breaker, rate cap or invalid answer returns the heuristic's answer. Critical events are never sent to a model; a model can only answer standard or background; it sees redacted titles and flags only, and digest groups and counts always come from the heuristic. New `GET /api/attention/status` (admin), `source` on digests and explanations, `ATTENTION_PROVIDER`, `OLLAMA_URL`, `OLLAMA_MODEL`, `ANTHROPIC_API_KEY`, `ATTENTION_MODEL`, `ATTENTION_TIMEOUT`, `ATTENTION_MAX_CALLS_PER_MIN`, and a "Written by" badge on digests and explanations. No database change. 214 Vitest tests; Go module passes. Tested against fake model servers only; not run against a real Ollama or the real Claude API.
- Milestone 25 (Attention Intelligence, see [milestone-25.md](milestone-25.md)): new `pkg/attention` (Layer 2) with `Classifier`, `Summarizer` and `Explainer` interfaces and a deterministic heuristic implementation that needs no model. Rules can opt in with `adaptive` so Attention may move quiet events to the digest; a guard keeps critical events away from it and rejects any attempt to escalate; a person's override outranks it. Digests of held events with highlights, stored, optionally delivered and made on a schedule or on request; plain-language explanations of any decision. New `GET /api/digests`, `POST /api/digests/generate`, `GET /api/explain/{id}`, table `digests`, `ATTENTION_CLASSIFY`, `ATTENTION_DIGEST_EVERY`, `NOTIFY_DIGEST_CHANNELS`, a Digests screen, an "Explain in words" button and an adaptive switch on rules. Background events with nowhere to go are now held for the digest. 211 Vitest tests; Go module passes. No language model yet; PostgreSQL digest store not run against a real database.

### Changed
- **Breaking (console):** unread state now comes from the service (`/api/notifications`), so the console needs a service from this version. Read ids kept in the browser are sent once and forgotten. CORS now allows PATCH and DELETE.
- Removed the old list, sheet and filter code (`Ledger`, `EventSheet`, `lib/filters`, `useRead`), replaced by `features/inbox`.
- **Breaking (console):** the dashboard is rebuilt; it needs `GET /events`, so it requires a service from this version. The API key is now entered in Connection settings (per tab) instead of read from `VITE_API_KEY` alone. `docker-compose.yml` allows the origins `http://localhost:3000` and `http://localhost:5173`.
- Web job in CI runs `npm test` before the build. Generated `tsbuildinfo`, `vite.config.js` and `vite.config.d.ts` are no longer tracked.
- **Breaking (security):** protected routes now fail closed. With no `API_KEY` they return 503 unless `ALLOW_UNAUTHENTICATED_API=true`. `/health` no longer needs a key. CORS is closed unless `CORS_ALLOWED_ORIGINS` lists the origin. `/notify` rejects non-https or non-allow-listed webhook URLs and invalid recipients (400).
- **Breaking (API):** `GET /metrics` now returns Prometheus text instead of JSON. Webhook event IDs are `github-<event>-<delivery id>`; a redelivery returns `200 {"status":"duplicate"}`. Logs use `http_status` instead of `status`.
- **Breaking (internal API):** `event.Repository` gains `Exists`; `dedup.Deduper.Check` takes a context and returns an error and gains `Forget`; `db.Connect` takes a `PoolConfig`; `pipeline.Pipeline.Handle` can return `ErrDuplicateDelivery`.
- Critical events now also reach Slack and Teams (previously only email was sent from the pipeline) and every channel is attempted even if another fails. `/notify` emails no longer carry the `[n8n agent]` subject prefix.
- Dedup key for `push` events includes the head commit, so different pushes are no longer merged.
- Go toolchain pinned to 1.26.10 (clears standard library vulnerabilities); Go Dockerfile rewritten (multi-stage, non-root, health check); CI adds lint, `govulncheck`, PostgreSQL integration tests, an 80% coverage gate, and `mvn verify`; k8s manifests read secrets from a Secret and define probes.
- **Breaking (internal API):** `event.Repository`, `delivery.Provider`, `delivery.Service`, `pipeline.Handle`, `notification.NotificationService`, `learning.Summarize`, `db.Connect` and `db.Migrate` take a leading `context.Context`; `server.NewServer(ctx, cfg, logger)` and `Server.Run(ctx)` changed to match.
- `notify` handler: 500 responses no longer include internal error text; `notification.ErrInvalidRequest` maps to 400.
- Commit messages no longer carry a Co-Authored-By trailer; earlier local commits were rewritten to match.

### Fixed
- Request logs and metrics always reported status 200.
- `PostgresRepository.List` failed on NULL `repository`.
- Policy rules with an unknown `attentionClass` (for example `critcal`) were silently treated as non-critical; they are now rejected at load.
- Webhook event IDs could collide (nanosecond timestamp); a failed save made GitHub's retry look like a duplicate and be dropped.
