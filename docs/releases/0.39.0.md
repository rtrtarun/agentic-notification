# Release 0.39.0

The first release since 0.36.0. It brings the Java service to parity with Go for everything except channels, metrics, the inbox and identity extras; adds offline, approval-gated learning to both services; and gives Java agent traces and an MCP server. Milestones 37, 38, 39a and 39b. Records: [milestone 37](../archived/milestones/milestone-37.md), [milestone 38](../archived/milestones/milestone-38.md), [milestone 39](../milestones/milestone-39.md); the running history is [CHANGELOG.md](../CHANGELOG.md).

## Highlights
- **Learning that waits for a person.** A background run reads stored feedback and proposes small, bounded score adjustments for the built-in heuristic (Go and Java). **Nothing changes until an admin approves**, every approval is audited, and retiring an adjustment restores the old score. Critical events are never counted or adjusted, and a person's always/never override still wins.
- **Java feature parity.** The Java service now has rule predicates and per-rule channels, feedback and always/never overrides, heuristic Attention Intelligence (classifier, explanations, digests, the attention budget), learning suggestions and score tuning, agent steps and traces, and the MCP server, each proven against Go by a shared contract file (17 files in all).
- **MCP from either service.** `POST /api/mcp` works on Go and Java with the same four tools, and Go's stdio `mcp-server` can point at either.
- **One queue owner.** `DISPATCHER_ENABLED=false` lets one of two services on a database leave the delivery queue to the other.

## What changed
- **Go:** offline score tuning (`/api/learning/runs`, `/api/learning/adjustments`, approve, reject, retire; new tables `learning_adjustments` and `learning_runs`); `DISPATCHER_ENABLED`; event lists break `created_at` ties by `id` in PostgreSQL and memory, so traces order same-instant steps the same way every time; MCP argument refusals are now plain words (`unknown argument "x"`, `argument limit must be a whole number`) instead of Go's JSON library text.
- **Java:** rule `payloadMatch` and `channels`; `POST /feedback` and `/api/overrides`; the heuristic classifier, `GET /api/explain/{id}`, digests (`/api/digests`) and the attention budget (shared with Go through Redis); learning suggestions and score tuning; `POST /api/events`, `GET /api/traces`; `POST /api/mcp`; `DISPATCHER_ENABLED`.
- **Contract:** files 11 to 17 added; both contract runners can check an empty body and the JSON inside an MCP tool result.
- **Docs:** status, Java service and architecture documents brought up to milestone 39b; finished milestone records and superseded notes moved to the archive; the roadmap runs to milestone 49.

## Upgrade notes
1. **Database:** the first start of the Go service adds `learning_adjustments` and `learning_runs` (idempotent). Nothing to run by hand. The Java service waits for the Go service's migration; it never migrates.
2. **Java now judges standard events.** `ATTENTION_CLASSIFY` defaults to `true` and `ATTENTION_BUDGET_PER_HOUR` to `10` in Java, as in Go: adaptive standard events may move to the digest, and standard interruptions over 10 an hour are held for the next digest (never dropped). Set `ATTENTION_CLASSIFY=false` or `ATTENTION_BUDGET_PER_HOUR=0` to keep 0.36.0 behaviour. Critical events are unaffected.
3. **Two services on one database:** run one queue dispatcher (`DISPATCHER_ENABLED=false` on the other), one digest schedule (`ATTENTION_DIGEST_EVERY=0` on the other) and one learning schedule (`LEARNING_TRAIN_EVERY=0` on the other; it is `0`, manual, by default).
4. **New settings, all optional:** `DISPATCHER_ENABLED`, `OVERRIDES_ADMIN_ONLY`, `LEARNING_MIN_SIGNALS`, `LEARNING_LOOKBACK`, `LEARNING_MIN_PEOPLE`, `LEARNING_MAX_ADJUSTMENT`, `LEARNING_HALF_LIFE`, `LEARNING_TRAIN_EVERY`, and in Java the attention settings above. Invalid values stop the service at start.
5. **Deploy a version tag:** point the host at `notification-service:0.39.0` (and `notification-service-java:0.39.0`), then check `GET /health` returns `"version": "0.39.0"`. The host is not redeployed by the release; trigger it.
6. **MCP clients** that matched on the old Go error text for bad tool arguments get the new plain wording.

## What was checked
- **CI** on `master` after merging milestone 39b (run 44879871735): `go-service` (including `-race`, golangci-lint, govulncheck and the PostgreSQL 16 and Redis 7 integration tests), `java-service`, `web` and `python-sdk` all passed.
- **Locally:** the Go suite, `go vet` and the integration tests against PostgreSQL 16 and Redis 7; Java `mvn verify` (376 tests offline at 39b; 387 with PostgreSQL and Redis at 39a); all 17 contract files in both services.
- **Both services on one database:** feedback in one service and a learning run in the other gave the same adjusted score in both (38c); one agent run published through both gave identical traces (39a); Go's stdio MCP server answered against the Java jar as against Go (39b).
- **Not checked:** a real MCP client and trace viewer (slice 39d); Ollama, Claude, Novu, SNS and OpenID Connect against real services; sign-in in a browser against the live service; whether the live service has moved to this release.

## Known issues
No ingestion rate limiting, and a critical event can be sent twice if the same delivery arrives twice at once (both milestone 44); per-address limits are shared by everyone behind a proxy; an approved member sees every event (one workspace); the inbox, digests, learning, traces and MCP reads look only at the newest 1000 events (milestone 42); the Java service has no SMS, Novu, metrics, inbox, retention, single sign-on or language model yet. The full list is in [implementation-sync.md](../implementation-sync.md).
